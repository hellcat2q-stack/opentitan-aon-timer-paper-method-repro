# 阶段 03：DUT 与源码锁定：实施记录

## 做了什么

在服务器专用根目录 `$ROOT` 下锁定 OpenTitan revision `9f20940d494a223cc950a5b98f748fb28109d458`，核对 AON Timer DV 配置和 RTL 文件，使用隔离 FuseSoC/Edalize 兼容层完成 VCS build、coverage smoke 和直接 URG 报告。

## 为什么这么做

阶段 02 的 FuseSoC 2.4.5/Edalize 0.6.3 不能直接消费目标 revision 的 primgen GAPI 输入；目标源码要求 FuseSoC `ot-0.5.dev0` 和 Edalize `0.4.0`。兼容依赖只放在服务器 `runtime/stage03_compat`，原始目标源码保持不改，避免把工具兼容改动混入 DUT。

## 怎么做

1. 服务器源码目录的 `git rev-parse HEAD` 为目标 revision；源码状态在 build 前后均为空。AON Timer 配置、顶层、coverage environment、sequence list、RTL 和 testplan 的 SHA-256 见 `evidence/stage03_source_manifest.json`。
2. 通过 `PYTHONPATH` 前置源码形式的 FuseSoC `ot-0.5.dev0` 与 Edalize `0.4.0`，并使用 VCS P-2019.06-SP1 wrapper 移除该版本不支持的 `-xprop=mmsopt`。旧 Git 的 `git -C` 兼容 shim 使 DVSIM 能读取 revision。
3. build 命令固定 `--local --max-parallel 1 --build-only --build-timeout-mins 30 --fixed-seed 42 -i aon_timer_smoke`，返回码 0；随后以同一 `simv` 做 coverage smoke，返回码 0、1/1 通过。
4. 对该 smoke 的单个 VDB 直接运行 URG `-metric group -format text`，不使用目标 commit 之外的四个 `.el` 文件；URG 返回码 0，报告摘要和服务器文件哈希见 `evidence/stage03_run_summary.json` 与 `evidence/stage03_server_hash_index.txt`。

## 文件放哪里

本阶段公开证据放在本目录；商业仿真数据库、simv、许可证和完整日志只保留在学校服务器隔离目录。

## 验收与局限

build、coverage smoke 和直接 URG 均返回 0；阶段 03 验收通过。DVSIM/URG 的 smoke coverage 仅证明构建和报告链路可用，不是论文表 II 的 coverage 结果。目标 revision 没有跟踪 `hw/ip/aon_timer/dv/cov/*.el`，这些辅助文件未进入最终 URG 命令；正式 bin 分母留到阶段 04 按目标 revision 的实际报告冻结。
