# 阶段 05：初始语料：实施记录

**状态：原始语料完成；runner timeout 参数缺陷已修复并有选择地重放（2026-11-01）。**

## 做了什么

- 根据阶段 04 清单，选用 smoke、prescaler、jump、stress-all 四条核心 UVM sequence，每条尝试运行 10 次，共 40 条独立仿真。
- 预注册本地 base seed 505，通过 `random.Random(505)` 和 sequence-major 任务顺序产生各 run seed；使用 4 并发 worker，单次 VCS/URG 宿主 timeout 均为 20 分钟。
- 使用阶段 03 构建的 `simv` 和正确 `dv_root=<OPENTITAN_ROOT>/hw/dv` 环境。每条仿真分别产生 VDB、运行日志、返回码、UVM marker、URG 报告、runtime 数据和哈希清单。
- 原始 40 次 VCS/URG 均返回 0；35 次 UVM PASS。其余 5 个 stress-all run 在 200 ms 触发 `[PH_TIMEOUT]`。对照官方 `stress_all_test.hjson` 后，确认 runner 漏传 `+test_timeout_ns=10000000000`。
- 修复 runner 并保留原始结果，以原 seed 单独重放 5 次：4 次 UVM PASS，1 次不再超时但出现 `intr_state` 检查错误（期望 0、读回 2）。原始 manifest 未改写，也没有覆盖失败证据。
- 将重放独立记录为补充证据；完整 VDB、URG 报告和日志仍留在服务器。阶段 06 接受原始 35 个 PASS 和重放 4 个 PASS，共 39 次；6 个失败尝试排除。

## 为什么这么做

初始语料需要为每条预先选定的 sequence 提供固定次数、可回放的随机 seed 和原始 coverage 报告。论文没有公开作者的初始语料内容、次数和 seed，因此本阶段记录本项目设置，不宣称其等同论文作者输入。原始失败及其修复重放均分开保留，重放不替换原始结果。

师兄的 `sequence_based_parallel_test.py` 使用旧 Verisim 配置格式，本阶段没有将其 UART 入口硬套到 VCS。新 runner 保留“每条序列固定运行数、并行执行、逐条 seed 和结果落盘”的用途，并直接调用已验证的 AON Timer VCS 仿真入口。

## 怎么做

- 原始 protocol：4 sequences × 10 runs，base seed 505，seed 派生规则和所有 seed 写入 manifest；4 并发，host timeout 20 分钟。
- 仿真参数：`+cdc_instrumentation_enabled=1`、`+ntb_random_seed=<seed>`、`+UVM_TESTNAME=aon_timer_base_test`、对应 `+UVM_TEST_SEQ=<sequence>`、`+en_cov=1`、line/cond/fsm/tgl/branch/assert。
- 单次 UVM 和 URG 流程由 `tools/run_aon_timer_initial_corpus.py` 执行。修复版 runner 对 stress-all 传入官方 10 秒仿真时限并将宿主时限调至 180 分钟；重放只选择原 global run ID 32、34、35、38、39。VCS stderr 合并进每次独立完整日志；不自动重试。
- VCS 返回码为 0 不等于 UVM 通过；以 UVM `TEST PASSED CHECKS`、`UVM_ERROR`、`UVM_FATAL` marker 分类。`PH_TIMEOUT` 的 VDB/URG 作为部分失败诊断保存，排除在成功语料之外。

## 验收与局限

原始 40 次计划尝试、40 个 VDB 和 40 个 URG dashboard 都已生成；UVM 为 35 PASS、5 PH_TIMEOUT。修复重放的 5 个 VCS/URG 均返回 0，UVM 为 4 PASS、1 UVM_ERROR。原 5 次失败的根因是漏传官方仿真时间参数；重放失败 `intr_state` 错误仍被保留，不做第三次尝试。

阶段 05 dashboard 显示 4525 个 group bins，仅作运行记录；阶段 06 从详细 bin 表及 VCS 累积 coverage XML 核验并冻结 4507 个分析 bin。初始语料及其 group score 不是论文最终 coverage 或 table-II 对照结果。
