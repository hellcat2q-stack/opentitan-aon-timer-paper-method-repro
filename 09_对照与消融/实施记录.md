# 阶段 09：对照与消融：实施记录

## 做了什么

已完成论文表 II 中 `RandomSelection` 的独立 VCS 基线：1000 次提交、10 个并发 worker、logical batch size 10、seed 42、39 条初始语料和 4507-bin 冻结口径。新增 `algorithm_source/run_vcs_random_selection.py`，直接调用 VCS/URG 适配器，不调用 UCB policy、target steering、Bayesian training 或 coverage replay。

## 为什么这么做

论文对 RandomSelection 的定义是从可用测试序列池随机选序列。作者没有公开完整 AON Timer pool，所以本复现使用阶段 04/06 固定的四条核心序列，均匀、有放回抽样；这项参数缺口单独记录，不能把本地 pool 当成作者原始 pool。

## 怎么做

smoke 10 已通过独立审计后启动 1000-submit 运行。每次完成后立即补位，失败仍计入预算且不产生 coverage reward；每个运行保留 VCS/URG/UVM 结果，事件链、seed、vector 和累计并集由审计脚本核验。

## 文件放哪里

本阶段公开证据放在本目录；商业仿真数据库、simv、许可证和完整日志只保留在学校服务器隔离目录。

## 验收与局限

10-submit smoke：10/10 通过，最终并集 237/4507。正式运行：1000/1000 通过、0 失败、0 重试；最终并集 259/4507（5.746616%），相对初始并集新增 26 bins；累计 simulator CPU runtime 65079.61 秒，walltime 8153.19 秒；最大并发 10。序列使用次数为 smoke 243、prescaler 243、jump 250、stress_all 264。两份独立审计均通过：事件链/seed/vector/reward/UVM/补位审计，以及逐 run 均匀有放回 sequence schedule 审计。论文 RandomSelection 参考为 16.67%、15355.71 秒、4450.20 秒；本地 coverage 少 10.9234 个百分点。论文未公开完整 sequence pool 和作者 seed；本地结果仅表示四序列 pool 的复现。现场 coverage 分母沿用阶段 06 的 4507-bin URG identity 口径，尚未独立证明与论文 bin 身份完全等价。
