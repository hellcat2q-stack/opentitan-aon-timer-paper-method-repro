# 八测试池实验（2026-11-19）

本分支用于评估从官方 AON Timer 17 个 DVSIM test 中选取 8 个代表性 test 后，Full、消融和 RandomSelection 的覆盖变化。原有四序列结果保持不动，新的运行目录使用 `stage09_8test_*_20261119` 前缀。

## 固定的 8 个 test

| 官方 test | 实际 sequence | 额外 run option | 选择理由 |
| --- | --- | --- | --- |
| `aon_timer_smoke` | `aon_timer_smoke_vseq` | 无 | 基本唤醒和看门狗行为 |
| `aon_timer_prescaler` | `aon_timer_prescaler_vseq` | 无 | 唤醒分频行为 |
| `aon_timer_jump` | `aon_timer_jump_vseq` | 无 | 阈值和计数器跳转 |
| `aon_timer_stress_all` | `aon_timer_stress_all_vseq` | `+test_timeout_ns=10000000000` | 多序列压力组合 |
| `aon_timer_intr_test` | `aon_timer_common_vseq` | `+run_intr_test` | 中断 CSR 行为 |
| `aon_timer_csr_rw` | `aon_timer_common_vseq` | `+en_scb=0`, `+csr_rw` | CSR 读写行为 |
| `aon_timer_mem_walk` | `aon_timer_common_vseq` | `+en_scb=0`, `+csr_mem_walk` | 地址/寄存器 walk |
| `aon_timer_tl_errors` | `aon_timer_common_vseq` | `+run_tl_errors` | TileLink 协议错误处理 |

选择规则是保留全部 4 个 AON Timer 专用行为入口，再加入中断、CSR、内存访问和 TileLink 错误四类代表性测试。`stress_all_with_rand_reset`、其它重复 CSR 变体、`tl_intg_err` 和 `sec_cm` 被排除；完整排除清单和源码版本见 [catalog](../configs/aon_timer_8test_catalog.json)。

这里的 8 个 test 是 8 个可调度的 DVSIM test 配置入口，其中 4 个入口使用 `common_vseq`，通过官方 plusarg 区分具体行为。它们不是 8 个不同的 SystemVerilog sequence 类。

## 运行约定

本轮继续使用冻结的 39 条初始覆盖向量、4507 个 bin、751 个 cluster、V30 `simv`、10 个 worker、logical batch size 10、100 个 batch、每方法 1000 次提交、seed 42。初始 39 条向量来自原四条核心 sequence；新增的 4 个 common test 在在线阶段没有历史向量，UCB 冷启动时按策略回退到完整 8 项池。这一点与“先为 8 个 test 各生成初始语料”的实验不同，必须在报告中单独标注。

服务器项目根目录中执行：

```bash
python3 09_对照与消融/tools/run_stage09_matrix_v30.py \
  --root "$ROOT" --prepare

python3 09_对照与消融/tools/run_stage09_matrix_v30.py \
  --root "$ROOT"
```

脚本会先运行策略行为测试，再依次执行 6 种方法的 30 次 smoke 和 1000 次正式运行。它要求 `$ROOT/scratch/stage08_v30_wkup_phase_bound_20261111`、VCS `simv`、URG、初始 CSV、cluster mapping 和 canonical report 已存在；这些服务器文件不会提交到 GitHub。失败尝试计入预算，不重试，也不把 smoke 拼入正式结果。

单独启动 RandomSelection 时，可调用 `run_stage09_v30.py` 并传入 `--catalog configs/aon_timer_8test_catalog.json`；矩阵脚本已经自动传入该参数。所有正式结果应写入 `runs/stage09_8test_<Method>_full1000_20261119`，脱敏导出写入 `evidence/stage09_8test_<Method>_full1000_20261119`。

当前工作站没有学校服务器上的 VCS `simv`、许可证、VDB 和 URG 原始目录，因此本分支先提交可审计的 catalog、调度器和运行入口；实际 6×(30+1000) 仿真必须在具备这些依赖的服务器上执行。运行完成后，`summary.json`、`protocol.json`、`audit.json`、`union_audit.json` 和比较图应作为本分支的脱敏证据提交。
