# v20 / v22 两层 UCB Full 对照

两组均完成 1000 次提交，使用同一组 1000 个 seed（seed=42）、39 条初始语料、4507-bin 覆盖身份、751 个 cluster、10 个 worker 和连续补位策略。配对脚本核对了预算、seed、输入语料、映射、解析器、奖励和失败规则，状态为 `completed`。

| 指标 | v20 控制组 | v22 处理组 |
| --- | ---: | ---: |
| 接受 / 失败 | 1000 / 0 | 996 / 4 |
| 覆盖 | 1739/4507（38.5844%） | 4105/4507（91.0805%） |
| 超出初始 508-bin 的新增覆盖 | 1231 | 3597 |
| 序列选择：stress-all / jump / smoke / prescaler | 64 / 738 / 100 / 98 | 831 / 129 / 22 / 18 |
| 累计 simulator CPU 时间 | 18,385.44 秒 | 169,428.39 秒 |
| wall time | 5,363.04 秒 | 22,073.08 秒 |

v22 比 v20 多覆盖 **2366 个 bin（+52.4961 个百分点）**。两组的独立事件/向量/奖励审计都通过。原始 VDB 由 URG 分别合并复核：v20 合并 39 个初始库和 1000 个在线库，得到 1739/4507；v22 合并 39 个初始库和 996 个成功在线库，得到 4105/4507。两组都与逐次向量并集完全一致，4507 个定义和命中身份逐 bin 一致。

v22 的 4 次失败均为 stress-all 的 WKUP scoreboard 断言失败，按预注册协议计入预算、不重试且不给覆盖奖励。v22 的序列不是全选 jump，实际以 stress-all 为主；v20 则以 jump 为主。v22 的累计 CPU 时间约为 v20 的 9.2 倍，wall time 约为 4.1 倍；覆盖提升伴随明显更高的仿真成本，不能只比较覆盖率。

这是一组单 seed 的 UCB 改动前后对照，不证明统计显著性，也不是 UCB 对 RandomSelection 的比较。连续补位会受任务完成顺序影响；共享服务器 wall time 也不能直接当作算法性能指标。所有百分比都是本地项目结果，不是论文原始数据。
