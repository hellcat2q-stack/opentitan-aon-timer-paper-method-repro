# 低覆盖原因与独立 URG 复核（2026-11-09）

本次分析发现：解析问题仍未完全修复。V19 调度器记录的 832/4507（18.4602%）是其 Python 向量口径的结果；把同样的 39 条初始语料和 1000 次在线运行的原始 VDB 直接交给 URG 合并后，详细 bin 表得到 **1191/4507（26.4256%）**。现有 `summary.json`、`audit.json` 和曲线保留为历史记录，不改写为独立复核结果。

本次没有重新仿真，没有修改算法、SV 源码或旧数据库。三个新合并数据库和完整 URG 报告均写入服务器专用 scratch 子目录 `stage08_v19_parser_diagnosis_20261109T151143/`；本地只保存脱敏摘要、已编译源码片段和哈希。

## 1. 用独立数据库合并核对最终覆盖

| 数据范围 | 数据库数 / URG 报告中的 test 数 | Python 向量并集 | URG 详细 bin 并集 |
| --- | ---: | ---: | ---: |
| 初始语料 | 39 / 39 | 233/4507（5.1697%） | 508/4507（11.2714%） |
| 仅本轮在线运行 | 1000 / 1000 | 790/4507（17.5283%） | 1009/4507（22.3874%） |
| 初始语料 + 本轮在线运行 | 1039 / 1039 | 832/4507（18.4602%） | 1191/4507（26.4256%） |

三个 URG 命令均返回 0，`tests.txt` 分别确认 39、1000、1039 个 test，详细 bin 分母均为 4507。命令沿用该项目的 group coverage、ratio、LRM bin name、instance score 和完整 missing-bin 输出选项。最终累计覆盖比 Python 记录多 359 个 bin，差约 7.9654 个百分点。按数据库合并口径，本轮比初始语料新增 **1191−508=683** 个 bin，不能用修正后的最终值减旧的初始值 233。

URG dashboard 是另一项口径：最终 1190/4525（26.2983%），与本项目的详细 bin 口径 1191/4507 分开保存。这里约 0.13 个百分点的差异不能解释与论文约 75% 的全部距离。还需向作者核对相同 coverage 类型、模型配置、序列池和初始语料；不能仅因为数字不同就改分母或去掉未覆盖 bin。

这次证明的是统计确实漏计；修正统计本身不会让 DUT 多执行任何行为。错误反馈还可能改变 UCB 后续选择，所以完全修复反馈后仍需新的在线实验，不能通过事后重算声称复现了另一条正确调度轨迹。

## 2. 解析器还存在的问题

V19 已修正部分自动数值 bin 和显式标签，但 `tools/run_vcs_ucb_paper_ucb_v19.py` 第 91–100 行仍对 cross bin 使用位置 `zip`；第 220–230 行还存在标签不一致、数量相同时的按行序回退。行数相同、每次命中总数相同，并不保证 bin 身份相同。不同物理 bin 被压到同一列会低估并集；同一物理 bin 被错分到不同列也可能虚增并集。

4507 列中有 **2080 个 cross bin（约 46.2%）**。在当前 Python 向量中，它们的覆盖从初始 41 个到最终仍是 41 个。URG 直接合并则显示，例如仅在线运行的 wakeup threshold × interrupt cross 已覆盖 96/1024。这个分布与剩余位置映射风险一致；跨全部 cross 的精确错位归属仍需稳定 ID 对照，不能只凭总数完成修复。

还发现 URG 合并报告分页为 `grp3.html`、`grp3_1.html`。当前 `parse_report()` 只遍历 `grp*.html` 并按 `grp(\d+)` 提取数字，`report_group_name()` 又只接受标题中的 `Group ::`。分页可能使用 `Group :`，首页还可能只有目录。现有解析器在直接读取合并报告时实际报错，说明格式兼容还缺少分页与页面角色处理。这不是本轮逐次报告必然漏页的证明，但必须纳入修复和验证。

建议以 VCS 数据库中的稳定 covergroup / coverpoint / bin ID 和 cross 成员元组为主键；HTML 兼容路径必须解析数值区间、成员 tuple 和分页，遇到身份不明时保留原始行并报错，禁止静默按行序配对。逐 bin 命中、逐 prefix 总数和独立 URG 合并并集都应一致，再称解析验收通过。此前 `audit=pass` 只证明现有向量、事件和奖励相互一致，不能证明其物理 bin 身份正确。

## 3. 初始语料、聚类和先验需要一起重建

用当前 V19 解析器重读 39 条初始报告，得到并集 454 个；URG 直接合并得到 508 个。两者均与冻结 CSV 中的 233 个不符，且 454 仍不是完全校正的结果。

因此只替换在线解析函数不够。Stage06 的 39 条初始向量、Stage07 的 cluster 映射、覆盖频率、自信息、初始 sequence 候选池和互信息先验均依赖这些数据。必须在统一稳定 bin 身份后从初始语料重算，再开始新版本的在线实验；新旧版本分别保留。78 个 cluster 是否合理，也应在重建后的真实覆盖矩阵上评估，而不是直接沿用旧映射。

## 4. 已编译 scoreboard 读错 wakeup count 的高 32 位

已核对本轮 V12 构建目录中的实际源码，而不只看本地候选补丁。`aon_timer_scoreboard.sv` 第 268–269 行为：

```systemverilog
csr_rd(.ptr(ral.wkup_count_lo), .value(rtl_count[31:0]), .backdoor(1));
csr_rd(.ptr(ral.wkup_count_lo), .value(rtl_count[63:32]), .backdoor(1));
```

第二行应读取 `ral.wkup_count_hi`。目前采样到的数值相当于 `{low32, low32}`，而不是实际 64 位 counter，因此即使寄存器按计划跳到了目标附近，coverage model 仍可能采到另一个 bin。这属于 testbench 采样错误，单独修 Python 不能恢复未被 coverage database 正确记录的物理计数。

独立 URG 的在线报告显示 wakeup count 仅覆盖 **2/512**，同组 threshold 覆盖 **94/512**；按当前解析器记录，47 次以 `wkup_count_cp` 为目标的定向运行全部未命中目标，而其他目标共 180 次均记录命中。该现象与源码错误一致；精确因果和修复效果仍应通过新构建中的高/低位不同的定向探针验证，检查实际寄存器、采样值和 bin 命中三者一致。修复后保留旧构建，禁止修改旧 VDB 来冒充重跑结果。

## 5. 未定向运行被兼容补丁限制在小范围

本轮实际编译的 `aon_timer_base_vseq.sv` 第 63–66 行：

```systemverilog
if (steer_field == 0) {
  wkup_thold inside {[1:10]};
  wdog_bark_thold inside {[1:10]};
  wdog_bite_thold inside {[1:10]};
}
```

这个限制原本用于避免普通从零开始计数的 sequence 等待巨大阈值超时，但也限制了未定向的 jump。大量更换 seed 的运行仍集中在相同的小区间，UCB 无法从这个执行空间中发现宽范围新 bin。

建议按 sequence 的实际能力设置约束：能写入接近阈值 counter 的 jump 使用宽范围阈值和受控距离；从零计数的 sequence 使用能在预算内达到的范围。分别验证边界、64 位高位写入、计时器隔离和中断清除时序，再允许宽范围配置。不能直接全局取消限制而让 smoke/stress-all 等待 64 位大阈值。

## 6. 两层调度与实际可执行目标脱节

本轮提交状态与当前解析器的奖励记录：

| 状态 | 运行数 | 记录的全局新增 bin | 记录的目标 cluster 新增 bin |
| --- | ---: | ---: | ---: |
| 可施加定向约束 | 227 | 527 | 217 |
| cluster 没有可映射 bin | 552 | 11 | 0 |
| 所选 sequence 不兼容 | 128 | 61 | 0 |
| 没有剩余可映射 bin | 93 | 0 | 0 |

以上新增归属受当前解析错误和并发完成顺序影响，修复后必须重算；它们只能用于定位调度模式，不能证明某 sequence 完全无覆盖价值。状态本身显示只有 22.7% 的提交得到了实际目标约束。先选 cluster、再选 sequence、最后才检查参数可实现性，会频繁落到无法执行所选目标的普通运行。

建议为每个 cluster 建立“尚未覆盖的目标 bin → 支持的 sequence → 可实现参数”映射；第二层在兼容候选中选择，并为未知能力的 sequence 保留有限探索。对连续无收益但可达性尚不明的目标设置冷却/降低采样频率，不能永久判不可达。互信息可作为扩充候选池的依据，不能代替 sequence 实际能否驱动目标的约束。无需把序列固定成 jump，也无需强求四种 sequence 数量均衡。

## 7. 完成前述修复后再调整 UCB

当前第二层的均值是 `0.8 × 目标 cluster 新增均值 + 0.2 × 全局新增均值`，但探索项分母使用 sequence 在所有 cluster 的全局成功运行次数。目标条件均值与全局计数的统计口径不一致；某 sequence 在其他 cluster 跑过很多次，会压低它在当前未试过 cluster 中的探索机会。建议将目标项使用的均值与观测数配对，未试过的 `(cluster, sequence)` 明确处理；混合全局收益则作为明确记录的扩展，与严格论文式目标奖励作受控对照。不能把 0.8/0.2 称为论文原始公式。

本轮覆盖始终低于 25%，因此第一层始终使用探索系数 5，第二层始终使用系数 3，后续较低探索阶段没有触发。用受误差影响的覆盖百分比决定探索阶段，会把解析错误进一步反馈进调度。建议按有效完成次数、置信度和剩余可达收益衰减探索，并评估滑动窗口或折扣均值，适应覆盖耗尽后收益下降。

当前记录中 73 个被选 cluster 有 48 个目标奖励一直为 0，这些目标合计占 640 次运行；这个零奖励可能部分由 cross 错位造成，修复前不能全部判为无效。CPU 时间则可独立确认：stress-all 170 次耗费 30389.84 秒，占累计仿真 CPU 约 83%；jump 470 次共 640.79 秒。预算以运行次数为主时，应同时报告覆盖/次和覆盖/CPU 秒，避免只因某序列短或初期收益高而长期偏选它。

## 建议执行顺序和验收标准

1. 完成稳定 bin / cross ID 和分页解析，离线重读已有数据；对照独立 URG 合并的 508、1009、1191 三个总数及逐 prefix 明细。
2. 在独立新源码副本修复 scoreboard 高位读取；用高低位不同的少量定向探针验证，确保 UVM 无错且目标 count bin 实际命中。
3. 重建初始语料、聚类和先验；按 sequence 能力修复未定向范围，扩展 cross 的参数/事件映射。
4. 对齐目标条件 UCB 的均值与计数，逐个评估探索衰减、运行时间惩罚和近期收益；保留混合 sequence 池，通过调度自然集中到有效候选。
5. 在同一构建、同一解析器、同一初始语料、相同预算/worker/seed 下进行对照。至少区分解析重算、SV 采样修复、steering 和调度策略的贡献。此前 v1、v3、v16、RandomSelection 都应重算后再比较，不能把旧解析百分比和新合并百分比直接解释为算法提升。

没有证据保证完成后达到 70%。当前可以确定：解析低估、scoreboard 采样错误和普通运行范围过窄是具体可修的问题；先解决它们，比继续在错误反馈上微调 UCB 系数更有依据。
