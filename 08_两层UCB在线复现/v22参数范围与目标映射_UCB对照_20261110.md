## 实际发现与修正

### 1. 配置 bin 的真实标签是数值区间

冻结的 4507-bin 映射中，实际配置标签包括 `name:bark[1:134217727]` 和 `name:wkup[0x2ffffffffffffff5:0x33fffffffffffff3]`。旧 mapper 只识别 `name:bark[序号]` 等形式，因此没有识别这些区间。这里是目标参数映射遗漏；v20 已修正的 XML 覆盖身份解析继续使用。

v22 直接读取标签中的十进制或十六进制上下界，检查字段名、位宽与上下界合法性，然后选择真实区间中点。配置类 173 个 bin 中，可映射数量从 8 增到 168；新增 160 个由 prescale/bark/bite 各 32 个区间和 wakeup 64 个区间组成。完整 universe 的可映射数量从 2056 增到 2216。剩余 bin 不做未经验证的强制参数映射。

真实 VCS 探针已分别验证 wakeup、bark、bite、prescaler 四类区间目标：UVM 通过，XML/URG 解析均为 4507 列，所选精确 bin 全部命中。依据是逐次真实覆盖数据库，不仅是随机化日志中的参数打印。

### 2. 按序列执行方式扩大参数范围

`jump_vseq` 在启动 timer 前写入接近阈值的随机计数器，适合探索完整 64/32 位阈值。v22 通过 `pre_randomize()` 判断当前实际序列类型，让未定向 jump 也使用全域分布：零值 10%、内部区间总权重 80%、最大值 10%。定向 jump 继续采用约束指定的目标值。

`smoke_vseq` 将计数器清零后等待中断，`stress_all_vseq` 会调用 smoke 子序列；它们若使用任意巨大阈值，可能长时间等不到中断。因此普通 smoke、stress 的父序列和 prescaler 保留安全的小阈值约束。stress 内部真正创建的 jump 子序列可以扩域。扩域由实际 sequence 类型控制，不把 smoke 改名或替换成 jump。

早期“所有序列全域随机”的验证在首批 10 次提交、0 次反馈时主动停止，保留服务器目录 `runs/stage08_vcs_ucb_smoke30_20261110_v21/`。它没有完成，不作为覆盖实验或对照结果。此前将 CPU 活动理解为正常长任务并不足以证明序列会及时结束；源码中的清零与等待路径才是缩小适用范围的依据。

### 3. 让零阈值目标满足计数约束

旧 base/jump 的定向 watchdog 路径同时要求正的 `wdog_count_gap` 和 `gap <= threshold`，零阈值目标会造成约束冲突。v22 在 threshold 为零时使用 count=0，否则才要求正 gap 和接近阈值的 count。bark_zero、bite_zero 两个真实探针均已 UVM PASS 且命中精确零值 bin。

### 4. 所有成功反馈都更新待选目标集合

旧 adapter 只在定向任务完成后更新 `steering_covered`。普通任务已覆盖的 bin 可能仍被当成尚未覆盖的目标。v22 在每次成功解析和接受反馈后更新这个集合，随后释放 reservation；失败任务仍不更新覆盖或获得奖励。

### 5. 保留 UCB 选择与覆盖口径

保留四个序列 arm、cluster/sequence 两层调度、在线新覆盖奖励、互信息/运行时间处理和连续补位。阈值目标仍要求 jump，prescaler 目标要求 prescaler；不强制所有任务选择 jump。最终序列占比以实际结果为准，没有加入人为配额。

两组均使用 v20 的稳定 XML bin identity、已修正 scoreboard 的源码谱系、同一份 39 条初始矩阵和 cluster map。初始覆盖并集为 **508/4507（11.2714%）**。没有缩小覆盖分母，也没有把旧 HTML 行序解析下的历史结果混入对照。
