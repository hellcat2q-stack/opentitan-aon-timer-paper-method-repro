# 阶段 01：论文协议与来源

## 公开论文事实

来源：`references/IM-1175.pdf`。论文 AON Timer 的表 II 比较 Full、NoIncrementalRefill、NoRuntimePenalty、RandomSelection、SequenceUCBOnly、ClusterUCBOnly；统一设置为 logical batch size 10、100 logical batches、1000 submitted simulations、10 parallel workers、同一 initial corpus 和同一随机种子。

论文报告的参考值：

| 方法 | Coverage (%) | Accumulated runtime (s) | Walltime (s) |
| --- | ---: | ---: | ---: |
| Full | 75.33 | 2928.25 | 4764.13 |
| NoIncrementalRefill | 75.33 | 3009.35 | 6160.74 |
| NoRuntimePenalty | 75.33 | 2949.53 | 4943.13 |
| RandomSelection | 16.67 | 15355.71 | 4450.20 |
| SequenceUCBOnly | 52.15 | 9594.78 | 4698.70 |
| ClusterUCBOnly | 27.17 | 47728.17 | 6629.73 |

这些数值是论文参考，不是本项目已复现结果。

## 不能假定的参数

论文正文没有公开完整 AON Timer sequence pool、每个序列的初始运行次数、每次随机 seed、完整 bin CSV、cluster 数量和作者提交脚本。阶段 01 只登记这些缺口；阶段 04–06 现场测量并固定值。若采用 seed 42 作为本地可复现协议，必须标注为本项目预注册值，而不是作者 seed。

## 方法定义

Full = information-aware cluster prior + cluster-level UCB + target-conditioned sequence-level UCB + continuous refill + runtime-aware penalty。

消融必须只移除一个组件或按论文名称实现：不连续补位、去运行时间惩罚、仅 sequence UCB、仅 cluster UCB，以及随机选择；所有其他输入、初始覆盖、预算和 worker 数保持一致。
